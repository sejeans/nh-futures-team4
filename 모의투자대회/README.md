## 1. 과제 개요

Mid Review(11/13) 현장에서 15:00\~18:00에 진행하는 해외 모의계좌 수익률 대회다. 규칙은 운영진 Discord 공지(11/10 확인)를 따랐다.

| 항목 | 내용 |
| --- | --- |
| 거래 시간 | 11/13(금) 15:00\~18:00, 모든 팀이 15:00에 동시에 시작 |
| 순위 | 15:00 평가금액 대비 18:00까지 번 금액. 발표장에 팀별 수익률 그래프와 순위를 실시간으로 표시 |
| 원금 | 해외 모의계좌 $100,000. 모든 팀이 같은 조건에서 시작하도록 11/12까지 해외 포지션을 전부 청산 |
| 사용 가능 전략 | 3, 4주차에 만든 **해외** 전략. 대회 시간에는 해외 계좌에서 대회 전략만 실행 |
| 실행 조건 | 주문 거절, 연결 끊김이 발생해도 3시간 동안 중단되지 않을 것. 손절 필수 |

4주차 국채선물 3년, 10년 스프레드는 국내 상품이라 대회에 사용할 수 없다. 그래서 3주차 해외 전략(ZN 시계열 모멘텀)을 대회용으로 수정했다.

목표는 다음 세 가지다.

1. 3시간 동안 프로그램이 중단되지 않고 진입, 손절 확인, 청산을 자동으로 실행한다.
2. 계약 수와 손절 폭은 지난 1분봉 시뮬레이션으로 손실 크기를 확인한 뒤 정한다. 방향 규칙은 3주차에 정한 것을 바꾸지 않는다.
3. 대회 이틀 전에 같은 시간대(15:00\~17:55)에 모의계좌로 리허설을 실행해 24계약 체결과 재시작 복구를 확인한다.

## 2. 전략 설명

방향은 3주차 실전 규칙인 시계열 모멘텀 12개월을 그대로 사용한다. 직전 거래일까지의 연결 일봉 종가(월물 교체 갭 조정)가 252거래일 전 종가보다 낮으면 매도, 높으면 매수다(Moskowitz, Ooi, Pedersen 2012). 이 규칙은 3주차 11/05에 백테스트 손익을 확인하기 전에 정했고, 대회를 위해 바꾸지 않았다. 계약 수, 손절 폭, 진입과 청산 시각은 대회를 위해 새로 정했다.

11/11 리허설의 신호는 직전 완성 일봉 11/10 종가 106.25(조정값)가 252거래일 전인 2025-11-19 종가 113.53125보다 낮아 **매도**였다.

### 대회 시간대의 ZN 변동 폭

ZNZ26 1분봉 8/24\~10/30 중 15:00 봉이 있는 49일로 계산했다([sim_compete.py](sim_compete.py)).

| 15:00\~17:55 | 중앙값 | 상위 10% | 최대 |
| --- | --- | --- | --- |
| 15:00 시가에서 17:55 종가까지 변화 폭 | 4틱 | 9틱 | 19틱 |
| 고가와 저가 차이 | 10틱 | 14.4틱 | 28틱 |

이 데이터는 서머타임 기간이라 미국 동부 02:00\~05:00에 해당한다. 대회 시간대(01:00\~04:00)와 1시간 다르다.

3주차 비용 기준(왕복 비용이 기대 변동 폭의 20% 이하)을 적용하면, 1계약 왕복 비용 약 2틱(호가를 넘는 비용 1틱 + 수수료 $16)이 변화 폭 중앙값 4틱의 51%여서 기준에 미달한다. 대회는 정해진 3시간 동안 거래하는 것이 참가 조건이므로, 이 기준으로 거래 여부를 정하지 않고 시뮬레이션을 계약 수와 손절 폭을 정하는 데 사용했다.

### 계약 수

순위는 수익률이 아니라 번 금액으로 정해지므로, 같은 가격 변화에서 계약 수가 순위를 결정한다.

| 계약 수 | 1틱 | 변화 폭 중앙값 4틱 | 손절 10틱 | 왕복 비용 (수수료 + 호가 1틱) |
| --- | --- | --- | --- | --- |
| 5 | $78 | $313 | $781 | 약 $158 |
| **24** | **$375** | **$1,500** | **$3,750** | **약 $759** |
| 48 (주문 가능 한도) | $750 | $3,000 | $7,500 | 약 $1,518 |

주문 가능 수량 48계약의 절반인 24계약으로 정했다. 48계약 주문의 체결 여부와 증거금이 부족할 때의 처리는 확인하지 않았다.

### 손절 폭 비교 (시뮬레이션)

24계약, 15:00 봉 시가에 진입, 매 분 종가로 손절 확인, 17:55 봉 종가에 청산. 진입과 청산마다 0.5틱 불리하게 체결하고 수수료 편도 $8/계약을 차감했다.

| 방향 | 손절 | 평균/일 | 중앙값 | 승률 | 손절 횟수 | 최악 | 최고 | 합계 | 최대 낙폭 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 시계열 모멘텀 | 8틱 | -$606 | -$1,134 | 41% | 11 | -$4,134 | +$6,366 | -$29,691 | -$30,378 |
| **시계열 모멘텀** | **10틱** | **-$262** | **-$384** | **45%** | **3** | **-$4,509** | **+$6,366** | **-$12,816** | **-$14,904** |
| 시계열 모멘텀 | 15틱 | -$292 | -$384 | 45% | 2 | -$6,759 | +$6,366 | -$14,316 | -$16,404 |
| 시계열 모멘텀 | 없음 | -$307 | -$384 | 45% | 0 | -$7,884 | +$6,366 | -$15,066 | -$17,154 |
| 항상 매수 | 10틱 | -$1,226 | -$1,134 | 27% | 6 | -$4,509 | +$6,366 | -$60,066 | -$60,798 |

- 손절 10틱은 이 시뮬레이션 손익을 확인하기 전에 정했다. 15:00\~17:55 고가와 저가 차이의 중앙값(10틱)과 같다. 8틱과 15틱은 비교를 위해 계산했다.
- 49일 동안 신호가 모두 매도였다. 그래서 시계열 모멘텀 결과는 "매일 24계약 매도"와 같고, 방향 예측력을 보여 주지 않는다. 매도가 항상 매수보다 손실이 작았던 것은 이 기간 15:00\~17:55에 ZN이 소폭 하락한 영향으로 판단된다[추정].
- 손절 8틱은 손절이 11회 발생해 손실이 가장 컸다. 고가와 저가 차이의 중앙값(10틱)보다 좁아 일상적인 변동에도 손절된다.
- 최대 낙폭은 49일을 매일 반복했을 때의 누적 손익 기준이다. 대회는 하루뿐이므로 하루 최악(-$4,509)이 더 직접적인 지표다.

### 규칙

| 구분 | 규칙 | 근거 |
| --- | --- | --- |
| 방향 | 시작할 때 1회 계산. 직전 완성 일봉 종가 < 252거래일 전 종가면 매도, > 이면 매수, 같으면 거래하지 않음 | 3주차 실전 규칙 (Moskowitz, Ooi, Pedersen 2012). 진행 중인 오늘 봉은 제외 |
| 진입 | 15:00에 목표 수량 24계약을 시장가로 주문 | 모든 팀이 15:00에 시작하고, 순위는 15:00 평가금액이 기준 |
| 손절 | 5초마다 청산 쪽 호가가 진입가(증권사 잔고 평균가)보다 10틱 이상 불리하면 전량 시장가 청산 | 2절 손절 폭 비교. 청산 쪽 호가를 써야 실제로 청산할 수 있는 가격으로 판단된다 |
| 시간 청산 | 17:55에 전량 시장가 청산 | 18:00 평가 전에 포지션을 정리한다. 체결 확인과 재시도에 5분을 남긴다 |
| 재진입 | 손절, 시간 청산, 비상 청산 후에는 재진입하지 않음 | 진입 1회로 정해 손실을 손절 1회분으로 제한한다 |
| 비상 청산 | `week03` 폴더에 `STOP` 파일을 만들면 다음 반복에서 청산 후 종료 | 프로그램을 끄지 않고 사람이 청산할 수 있게 한다 |
| 수량 맞추기 | 매 반복마다 증권사 잔고를 재조회해 목표 수량과의 차이만 주문 | 재시작하거나 주문이 일부만 체결되어도 같은 판단을 한다 |

### 실행 흐름

```
15:00 전  python compete.py --yes 실행 (리허설은 14:39)
          연결 일봉 조회 → 방향 계산 → compete_state.json 저장 → 15:00까지 대기
매 5초    1. 목표 수량 결정 (15:00 전 없음, 15:00~17:54 방향 × 24, 17:55 이후나 손절 후, STOP 파일이 있으면 0)
          2. 증권사 잔고와 평균가 조회
          3. 현재가와 호가 조회 → 손절 확인
          4. 잔고 = 목표면 대기. 다르면 차이만큼 시장가 주문
             → 주문내역으로 체결 확인 → 잔고가 바뀔 때까지 최대 30초 대기
          5. 1분마다 상태 기록 (포지션, 목표, 진입가, 현재가, 추정 손익)
          예외가 나면 기록하고 5초 뒤 1번부터 반복
목표 0이고 잔고 0  "종료: 잔고 0" 기록 후 종료
```

재시작하면 그날의 `compete_state.json`(방향, 진입 여부, 손절 여부, 종료 여부)을 읽고, 잔고는 증권사에서 재조회한다. 그래서 진입 후 재시작해도 재진입하지 않는다.

## 4. API 활용

| 용도 | API | 사용 위치 |

| 접근토큰 | `POST /auth-service/v1/token` | 한 번 발급해 재사용하고, 토큰 오류(`EGW018`, `EGW023`, `EGW052`)를 받으면 재발급 |

| 현재가 | `/trade/v1/overseas/price` | 5초마다 현재가, 매수 1호가, 매도 1호가 |
| 잔고 | `/trade/v1/overseas/open-interest` | 5초마다 순포지션과 평균가 (진입가로 사용) |
| 주문 | `/trade/v1/overseas/order` | 시장가 신규 주문 (`glb_ord_tp_cd` 1) |
| 주문내역 | `/trade/v1/overseas/order-history` | 주문번호로 체결 수량과 체결가 확인 |
| 누적손익 | `/trade/v1/overseas/cumulative-pl` | 리허설 후 실현손익과 수수료 확인 |

공통 처리는 2주차 [nh.py](../week02/nh.py)와 3주차 [nh_os.py](../week03/nh_os.py)를 그대로 사용한다.

- **호출 간격**: 시세 0.1초, 계좌 0.1초, 주문 0.2초, 인증 0.34초(운영안내 17p의 초당 한도 기준).
- **재시도**: 시세와 계좌 조회는 응답 지연, 5xx, 호출량 초과 시 최대 3회 재시도한다.
- **주문은 재전송하지 않는다**: 주문 응답을 받지 못하면 체결되었을 수 있으므로 재주문하지 않고 15초 뒤 잔고로 판단한다(운영안내 22p).
- **실계좌 주문 차단**: `NH_ENV=paper`가 아니면 주문 API를 호출하지 않는다.
- **응답 로그**: 모든 요청과 응답을 `results/api_log/`에 남긴다. 11/11부터 파일 이름에 PC 이름을 붙인다(`YYYYMMDD_PC이름.jsonl`).

## 6. 결과 분석

**1. 리허설에서 대회 조건에 필요한 동작을 모두 확인했다.**
15:00 진입, 1분 기록, 17:55 시간 청산, 잔고 0 종료가 계획대로 실행되었다. 중간에 PC를 옮겨 재시작했을 때 진입 상태를 복구하고 재진입하지 않았다. 대회 중 연결이 끊겨 재시작하는 경우에도 상태 파일과 증권사 잔고로 복구된다.

**2. 24계약은 시장가 한 번에 전량 체결되었다.**
체결가는 주문 직전 호가와 같았다. 48계약에서도 같은지는 확인하지 않았다. 모의 서버의 체결 방식이 실제 CME 호가 잔량을 반영하는지도 확인하지 못했다.

**3. 리허설 손실은 방향과 비용에서 각각 발생했다.**
가격이 5틱 상승해 매도 포지션에서 $1,875 손실이 났고, 수수료 $384가 더해졌다. 수수료는 24계약 왕복 기준 원금의 0.38%로, 가격이 1틱 유리하게 변동했을 때의 이익($375)보다 크다.

**4. 시뮬레이션의 평균 손익은 음수였다.**
손절 10틱 기준 하루 평균 -$262이고, 49일 중 이익인 날이 45%였다. 비용(하루 약 $759)을 빼기 전에는 49일 합계가 약 +$24,400으로 양수지만, 신호가 기간 내내 매도였으므로 방향 예측력의 근거가 아니다[추정]. 대회 결과는 하루 한 번의 결과라 이 분포 안에서 어느 쪽으로도 나올 수 있다.

### 실행 방법

```bash
pip install pandas numpy
# 저장소 루트의 .env에 해외 권한이 있는 모의 키를 NH_OVERSEAS_APP_KEY, NH_OVERSEAS_APP_SECRET으로 입력한다 (NH_ENV=paper)

python 모의투자대회/sim_compete.py           # 시뮬레이션 → 모의투자대회/results/sim_compete.json
cd week03
python compete.py --dry                       # 주문 없이 판단만 기록
python compete.py --yes                       # 대회 실행 (15:00까지 대기 후 시작)
```

비상 청산: `week03` 폴더에 `STOP` 파일을 만든다.

외부 코드: 없음. 운영진 [nh-futures-open-api](https://github.com/PetterChanHyuk/nh-futures-open-api) 코드는 사용하지 않았다. 사용 패키지: pandas, numpy.
